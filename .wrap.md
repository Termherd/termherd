# wrap configuration

## Canonical locations

- index: docs/src/SUMMARY.md (the book) and `.roadmap/features/` (status)
- lessons: AGENTS.md, the incident behind each rule in docs/agents/lessons.md
- skills: .claude/skills/
- decisions: docs/ARCHITECTURE.md and docs/PRD.md (no ADR directory)
- journal: none; CHANGELOG.md `[Unreleased]` for user-visible changes only
- tracker: github issues + the project board (Termherd org, project 1)

## Verification commands

- blocking: markdownlint-cli2
- blocking: just docs
- blocking: just roadmap (when `.roadmap/` changed)
- advisory: just board-check (needs a `project`-scoped token)

## Disposable zones

- docs/book/ (generated by `just docs`, ignored)
- .personal/ (briefs and reports, ignored)

## Commit conventions

- format: `<type>(<scope>): <the conclusion, lowercase>`
- no AI signature, no issue numbers in code comments; `Closes #NN` in PR bodies

## Notes

- `ROADMAP.md` is generated on the release branch: never edit it in a wrap.
- A book page restates code as prose: reconcile the README's matching
  paragraph too, which repeats much of the book (the zsh integration claim
  lived in both).
- Hand-kept lists of open issues drift; point at a label-filtered issue list
  instead (done for live-bridge.md and the README's MCP section).
- Worktrees here are shared with other sessions: uncommitted Rust changes in
  this worktree may belong to another session. Commit only your own paths.
- Piping a check into `tail` hides its exit status: run
  `set -o pipefail` first, or the commit after `&&` goes out on a failure.
