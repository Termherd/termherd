# Benchmark harness

Measures start-up, memory and CPU at rest, a burst of output, and the memory
left after it, so a claim against the PRD §7 budget comes with a command
anyone can replay. Not a CI gate: it needs Docker, takes minutes, and depends
on the machine.

## Run it

Needs Docker with a Linux engine, Bash (Git Bash on Windows), about 5 GB of
disk per image and network for the build.

```bash
just bench-build termherd     # ./bench/build-all.sh termherd
just bench termherd 3         # ./bench/run-all.sh 3 termherd
```

The image builds termherd at the `REF` pinned in
`bench/adapters/termherd.Dockerfile`. Another pushed ref:

```bash
BENCH_BUILD_ARGS="--build-arg REF=<commit>" ./bench/build-all.sh termherd
```

Results go to `bench/results/<tool>-rep<n>/` (gitignored): `metrics.txt`
(`#` lines for the environment, then one `S<n>` line per scenario),
`docker-stats.txt`, screenshots `s1.png` to `s5.png`, logs.
`summarize.sh` prints the medians.

| Variable | Default | Effect |
| --- | --- | --- |
| `BENCH_CPUS`, `BENCH_MEM` | `4`, `4g` | container limits |
| `BENCH_RESULTS` | `bench/results` | results folder |
| `BENCH_HISTORY_SESSIONS`, `_PROJECTS`, `_MB` | `13`, `3`, `40` | generated `~/.claude/projects` |
| `BENCH_REAL_HISTORY` | `0` | `1` copies the host's projects (never credentials); keep those results private |
| `BENCH_ADAPTERS` | empty | extra adapter folders, colon-separated |
| `BENCH_BUILD_ARGS` | empty | flags for `docker build` |
| `BENCH_SETTLE_PCT` | `50` | S4 "settled" threshold, % of one core |

The history is generated by default so no capture shows a real session title.
`run.sh` refuses to start while a container named `*bench*` runs: two runs
skew each other.

## Scenarios

| | Gesture | Measure |
| --- | --- | --- |
| S1 | start the app | seconds to the first painted pixel |
| S2 | one shell pane | memory after 30 s, mean CPU over 30 s |
| S3 | four shell panes | the same |
| S4 | `seq 1 500000`, then `cat` 50 MB | `duration_s` until the shell is done, `settle_s` until the app stays under `BENCH_SETTLE_PCT` for two 1 s windows; peaks over both |
| S5 | wait 30 s | memory and CPU over the next 30 s |

Read `settle_s` as the cost of a burst: the shell can finish while the app is
still parsing what it queued.

## Reading the numbers

- Docker has no GPU. termherd renders with Mesa lavapipe, so CPU includes
  rendering, and about 70 MiB of the app's memory is that renderer.
- Compare `app_only_pss_mb`. RSS counts shared pages per process; `cg_mem_mb`
  (what `docker stats` shows) is not a superset of it and does not compare.
- Memory is in MiB, CPU in % of one core.
- Use the median of three. Compare runs whose `#` lines match.

## Native Windows

Measures S1 and an idle window with no session (S0) on the host:

```powershell
.\bench\native\windows.ps1 -Exe C:\path\to\termherd.exe -Reps 3
```

It runs beside your own instance with a private home and TMP, which needs a
build whose lock follows `TMP` (PR #413); an older build exits with code 2.
It reports the working set (resident) and private bytes (committed); neither
is a PSS.

Not tooled: S2 to S5 natively (termherd ignores posted input, and real input
would take over yours), and macOS (would use a private `TMPDIR` and `HOME`,
then `ps` or `vmmap`).

## Adding an adapter

Two files in one folder, named after the tool: `<tool>.Dockerfile` (image
`thbench-<tool>`, everything pinned, writes `/bench-ref`) and `tool-<tool>.sh`
(the hooks listed at the top of `bench/lib.sh`). See
`bench/adapters/tool-termherd.sh`. Keep adapters for other tools outside this
repository and list their folder in `BENCH_ADAPTERS`.

GUI adapters click at fixed coordinates: if the window or sidebar layout
changes, `s2-open.png` shows whether the click landed.
